## 1. System Investigation & Environment Status

To run live integration tests for the Rust TeamSpeak 3 client, an active TeamSpeak 3.13.9 server instance is required. An investigation of the host environment was performed on Windows:

### 1.1 Command Probing Results
1. **WSL Probe (`wsl -l -v`)**:
   - **Command Result**: Exited with code 1.
   - **Output**:
     ```text
     The service cannot be started, either because it is disabled or because it has no enabled devices associated with it.
     Error code: Wsl/0x80070422
     ```
   - **Registry & Service Audit**:
     - Registry key `HKCU\Software\Microsoft\Windows\CurrentVersion\Lxss\{3a556e2b-3828-4015-8e21-257d984e38b3}` is registered with distribution `Ubuntu-24.04`, Version 2, VHD located at `H:\WSL\Linux\Ubuntu_2404\ext4.vhdx`.
     - Windows Service `WSLService` is currently configured with `Status: Stopped` and `StartType: Disabled`.
     - Attempting to configure/start `WSLService` via standard user token failed with `Set-Service: Access is denied` (requires Windows Administrator elevation).
2. **Docker Probe (`docker version`)**:
   - **Command Result**: Exited with code 1.
   - **Output**:
     ```text
     docker: The term 'docker' is not recognized as a name of a cmdlet, function, script file, or executable program.
     ```
   - Docker CLI and daemon are not installed on the system PATH.

### 1.2 Status: BLOCKED for Live Process Execution
Because neither WSL (disabled service) nor Docker is operational without administrative intervention, spawning the live Linux ELF server binary (`ts3server`) is blocked.

#### Resolution to Unblock Server Execution:
In an **Elevated (Administrator) PowerShell terminal**, run:
```powershell
Set-Service -Name WSLService -StartupType Manual
Start-Service -Name WSLService
```
Once enabled, the helper scripts can be invoked directly from any shell. Alternatively, install Docker Desktop to use the containerized fallback.

## 2. Server Architecture & Configuration Specifications

The Linux 64-bit ELF build of TeamSpeak 3 server 3.13.9 is extracted at:
- `D:\Dev\ts3-rust\.scratch\teamspeak3-server_linux_amd64\ts3server`

### 2.1 Listening Ports & Protocols
| Port | Protocol | Service / Function | Default Parameter |
| :--- | :--- | :--- | :--- |
| **9987** | **UDP** | Primary Virtual Voice Server (Client connection) | `default_voice_port=9987`, `voice_ip=0.0.0.0` |
| **10011** | **TCP** | ServerQuery interface (Raw telnet / text protocol) | `query_port=10011`, `query_ip=0.0.0.0` |
| **30033** | **TCP** | File Transfer subsystem | `filetransfer_port=30033`, `filetransfer_ip=0.0.0.0` |
| **10022** | **TCP** | ServerQuery SSH interface | `query_ssh_port=10022` |
| **10080** | **TCP** | WebQuery HTTP JSON interface (TS3 3.12.0+) | `query_http_port=10080` |

### 2.2 License Acceptance Mechanism
Verified against `ts3server` binary and `server_quickstart.md` (lines 20-35, 402-404):
The server requires affirmative license acceptance through any of three mechanisms:
1. **Marker File**: Empty file named `.ts3server_license_accepted` in the server root working directory.
2. **Commandline Parameter**: `license_accepted=1` passed directly to `./ts3server`.
3. **Environment Variable**: `TS3SERVER_LICENSE=accept`.

### 2.3 Commandline Invocation Matrix
For background daemon execution in WSL:
```bash
./ts3server \
    license_accepted=1 \
    default_voice_port=9987 \
    query_port=10011 \
    filetransfer_port=30033 \
    logpath='/mnt/d/Dev/ts3-rust/.scratch/ts3logs/' \
    daemon=1 \
    pid_file=ts3server.pid
```
For Docker container execution:
```bash
docker run -d \
    --name ts3server-test \
    -e TS3SERVER_LICENSE=accept \
    -p 9987:9987/udp \
    -p 10011:10011 \
    -p 30033:30033 \
    -v "D:/Dev/ts3-rust/.scratch/ts3logs:/var/ts3server/logs" \
    teamspeak:3.13.9
```

## 3. First-Run Credential Format & Log Parsing

Reverse-engineering the binary strings of `teamspeak3-server_linux_amd64/ts3server` reveals the exact first-run credential banners output when creating the default database (`ts3server.sqlitedb`):

### 3.1 ServerQuery Admin Account Banner (Offset 8075767 - 8076154)
```text
------------------------------------------------------------------
                      I M P O R T A N T                           
               Server Query Admin Account created                 
         loginname= "serveradmin", password= "<AUTOGENERATED_PASSWORD>"
         apikey= "<AUTOGENERATED_APIKEY>"
------------------------------------------------------------------
```
- **Username**: `serveradmin`
- **Password**: Random base64/alphanumeric string generated on database initialization.
- **API Key**: Query API key for HTTP/WebQuery authorization.
- **Parsing Regex**:
  - Password: `loginname=\s*"serveradmin",\s*password=\s*"([^"]+)"`
  - API Key: `apikey=\s*"([^"]+)"`

### 3.2 ServerAdmin Privilege Key Banner (Offset 8094924)
```text
------------------------------------------------------------------
      ServerAdmin privilege key created, please use it to gain 
      serveradmin rights for your virtualserver. please
      also check the doc/privilegekey_guide.txt for details.
       token=<AUTOGENERATED_PRIVILEGE_TOKEN>
------------------------------------------------------------------
```
- **Token**: Alphanumeric token (e.g., `token=43charBase64String...`) passed to client command `privilegekeyuse token=<TOKEN>`.
- **Parsing Regex**:
  - Token: `token=([A-Za-z0-9+/=_-]+)`

### 3.3 Target Credential File Format
Credentials extracted by `ts3server-start.ps1` are formatted into `D:\Dev\ts3-rust\.scratch\ts3-credentials.txt`:
```ini
# TeamSpeak 3.13.9 Server Credentials
loginname=serveradmin
password=<PASSWORD>
apikey=<APIKEY>
token=<TOKEN>
```

## 4. Helper Scripts Reference

Helper scripts are installed in [scripts/](file:///D:/Dev/ts3-rust/scripts):

### 4.1 Startup Script: `scripts/ts3server-start.ps1`
- **Path**: [ts3server-start.ps1](file:///D:/Dev/ts3-rust/scripts/ts3server-start.ps1)
- **Features**:
  - Auto-detects WSL vs Docker (`-Backend auto|wsl|docker`).
  - Creates `.ts3server_license_accepted` and specifies `license_accepted=1`.
  - Configures ports 9987 (UDP), 10011 (TCP), 30033 (TCP).
  - Routes logs to `.scratch\ts3logs`.
  - Spawns process as background daemon with `pid_file=ts3server.pid`.
  - Polls TCP port 10011 and verifies `TS3` ServerQuery handshake banner.
  - Verifies UDP port 9987 socket.
  - Automatically parses first-run logs and populates `ts3-credentials.txt`.
- **Usage**:
  ```powershell
  .\scripts\ts3server-start.ps1
  ```

### 4.2 Shutdown Script: `scripts/ts3server-stop.ps1`
- **Path**: [ts3server-stop.ps1](file:///D:/Dev/ts3-rust/scripts/ts3server-stop.ps1)
- **Features**:
  - Detects active running backend.
  - WSL: Reads `ts3server.pid`, issues `SIGTERM` (`kill -TERM`), followed by cleanup.
  - Docker: Gracefully stops container `ts3server-test` and removes it.
- **Usage**:
  ```powershell
  .\scripts\ts3server-stop.ps1
  ```
